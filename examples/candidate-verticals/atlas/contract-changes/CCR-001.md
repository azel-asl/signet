# CCR-001 — Frozen world definition fails the frozen world schema on `id` pattern

**Status:** PROPOSED (Muse → Fable review) · **Date:** 2026-10-07
**Raised during:** ATLAS V0 Milestone 1 (world + replay parity), strict loader implementation

## 1. Problem

The frozen world definition `fixtures/restaurant-v0/world.restaurant-v0.json`
does **not** validate against the frozen schema
`schema/atlas-world-definition.schema.json`, so the M1/M2 PASS WHEN criterion
"world.restaurant-v0.json validates against the schema and the semantic checks in
03-data-model.md, and loads" cannot pass with a contract-faithful strict loader.

`$defs/id` requires `^[a-z][a-z0-9_]*$`. The world file violates it at 10 pointers:

| Pointer | Value | Violation |
|---|---|---|
| `/metadata/id` | `restaurant-v0` | hyphens not in `[a-z0-9_]` |
| `/rules/0/id` … `/rules/8/id` | `R01` … `R09` | uppercase initial not in `[a-z]` |

Verified with an independent check: all 1,815 ledger lines validate against
`atlas-event.schema.json`, and all 6 snapshot/expected files validate against
`atlas-snapshot.schema.json` — the defect is confined to these 10 pointers.
The oracle (`oracle/generate.mjs`) never validates the world file, which is why
the defect survived to freeze.

Until this CCR is approved, the world-validation check is reported as **FAILING**,
not skipped (§3 of the handoff). The runtime keeps a strict default loader; the
parity demonstration proceeds downstream of the disputed check only through an
explicit, logged `allowDeviations: ['CCR-001']` affordance.

## 2. Proposed change (recommended: schema-side, option A2)

Keep `$defs/id` strict for entity ids. Add two targeted definitions and repoint
the two non-entity-id positions:

```diff
 "$defs": {
   "id": { "type": "string", "pattern": "^[a-z][a-z0-9_]*$" },
+  "rule_id": { "type": "string", "pattern": "^[A-Za-z][A-Za-z0-9_]*$" },
+  "world_id": { "type": "string", "pattern": "^[a-z][a-z0-9_-]*$" },
   ...
```

```diff
-    "id": { "$ref": "#/$defs/id" }, "name": { "type": "string" }, "version": ...
+    "id": { "$ref": "#/$defs/world_id" }, "name": { "type": "string" }, "version": ...
     (in `metadata.properties`)
```

```diff
-      "properties": { "id": { "$ref": "#/$defs/id" }, "kind": ...
+      "properties": { "id": { "$ref": "#/$defs/rule_id" }, "kind": ...
     (in `rules.items`)
```

Rationale: rule labels (`R01`) and the world's own name (`restaurant-v0`) are not
entity ids; the canonical-id guarantee (`stable, canonical, never a source
identifier`) stays intact for every entity, station, equipment, person, product,
step, relationship endpoint, alias target, and visualization object.

## 3. Affected fixtures and tests

- **Schema file** `schema/atlas-world-definition.schema.json`: hash changes
  (its verification key is "file sha256 at the reference commit" — informational;
  Fable records the new hash on acceptance).
- **No fixture regeneration needed.** World file, ledger, snapshots, expected
  files, and `manifest.json` are byte-identical; no `state_hash` moves.
- **Tests affected:** `test/schema.test.ts` → "valid world loads" flips from
  FAIL (10 pointers, asserting the exact defect) to PASS once the schema is
  updated. All other M1 tests are unaffected.

## 4. Migration impact

- Runtime code: none (the validator implements the schema as written; it accepts
  the new `$defs` without code changes).
- Oracle: none (it does not validate the world file).
- The `allowDeviations: ['CCR-001']` affordance in the Muse loader becomes
  unnecessary and is removed after acceptance.

## 5. Alternatives considered

- **B — world-side rename** (`R01`→`r01`, `restaurant-v0`→`restaurant_v0`):
  changes `world_sha256`, forces a Fable-side manifest regeneration, and leaves
  snapshot envelope `world` fields stale unless all 6 snapshot files are also
  regenerated. Larger blast radius for zero semantic gain; rejected.
- **C — loader leniency by default:** violates the contract's explicit
  "MUST NOT improvise" / strict-loader requirement; rejected.
- **A1 — relax `$defs/id` globally** (`^[a-zA-Z][a-zA-Z0-9_-]*$`): one-line change
  but weakens the entity-id canonicality guarantee the pattern exists to protect;
  rejected in favor of the targeted A2.

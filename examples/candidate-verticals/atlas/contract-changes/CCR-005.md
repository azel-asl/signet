# CCR-005 — M4 claim-id uniqueness, link-wide non-escalation, branch interval, item-work definition

**Status:** ACCEPTED by the spec owner, 2026-10-08. Amends `18-m4-diagnose-contract-and-muse-handoff.md`
and `schema/atlas-diagnosis.schema.json`. Raised by the independent M4 review of `muse/atlas-v0` @ `429c93f`.

## 1. Problems

1. **Unknown claim ids collide.** §C fixes `id = 'c:<kind>:<subject>'`. A station can carry two unknowns
   (for example `INSUFFICIENT_WINDOW` and `MODEL_UNEXPLAINED_IDLE` early in a day). Both get
   `c:unknown:<station>`, the validator rejects the duplicate, and the whole diagnosis fails.
2. **World-level unknown id violates the schema.** §J puts `subject = world id` on `RULE_NOT_APPLICABLE`.
   World ids allow hyphens (`restaurant-v0`, CCR-001), but the schema's id pattern does not.
3. **Non-escalation covers only `supports`.** E3 lets a deterministic claim be `limited_by` or `blocks`-linked
   to a `bounded` or `none` claim, so a deterministic overload could rest on an inferred limitation.
   No V0 pack emits inference, so this is latent, but it defeats the property M4 exists to guarantee.
4. **The facade cannot know the simulated interval.** §G requires simulated diagnosis only in `[tB, tH]`
   and `onset_in_parent` relative to `tB`, but §K's `diagnoseAtTime({ world, ledger, t, branch? })` carries
   neither. The review observed pre-branch history served as `SIMULATED` and states diagnosed past the horizon.
5. **"Item work" is undefined.** `assembly_blocking` speaks of an order's "remaining item work" without saying
   how item work is told apart from the order step. The implementation hard-coded a restaurant step name.
6. **`onset_in_parent` has no boundary rule** for an onset exactly at `tB`.

## 2. Why the frozen contract is insufficient

Items 1, 2 and 4 cannot be implemented correctly as written. Item 3 permits exactly what the contract's design
law forbids. Items 5 and 6 left choices that the first implementation made wrongly or not at all.

## 3. Normative changes

**C1 — claim ids.** Non-unknown claims: `c:<kind>:<subject>`. Unknown claims:
`c:unknown_<reason lower-case>:<subject>`, for example `c:unknown_model_unexplained_idle:st_fry`.
The subject segment allows `[a-z0-9_-]`. Ids stay unique per diagnosis; a pack emits at most one claim per
(kind, subject) and at most one unknown per (reason, subject).

**C2 — E3 over every link.** For each link, define the *dependent* and the *dependency*:

| rel | link `A → B` means | dependent | dependency |
|---|---|---|---|
| `supports` | A supports B | B | A |
| `limited_by` | A is limited by B | A | B |
| `blocks` | A blocks B (B is the downstream effect) | B | A |

E3 (replaces the old text): for every link, `rank(dependent.support) ≤ rank(dependency.support)` with
`deterministic = 2 > bounded = 1 > none = 0`. Applied edge by edge, this bounds every path. A claim of
`claim_class: inferred` is always `bounded` (E2), so a deterministic claim can never depend on an inferred one.

**C3 — branch interval in the facade.**
`diagnoseAtTime(input: { world; ledger; t; branch?; branch_interval?: { tB: number; tH: number } })`.
When the ledger classifies as simulated (`getStateAtTime` mode `SIMULATE`), `branch_interval` is required
(`DiagnosisError('BRANCH_INTERVAL_REQUIRED')`) and `t ∉ [tB, tH]` → `T_OUT_OF_RANGE`. For observed ledgers it
must be absent and the range is `[time.origin, time.end]`. The service passes the register's
`branch_point_t`/`horizon_t`. Pre-branch history is never relabelled simulated, and nothing past `tH` is diagnosed.

**C4 — item work.** An order's *item work* is its open work whose `step` is not a step of the world process with
`applies_to = 'order'`. "Only remaining item work is at `s`" means every item-work entry of the OPEN order has
`station_id = s`. Packs identify the order step only through that process, never by step name or id pattern.
The reference generator stays fixture-specific by design and is not a template for pack code.

**C5 — `onset_in_parent`.** `true` iff `onset_t < tB`, or `onset_t = tB` and the condition already holds in the
parent state reduced to `tB` (parent events only). Otherwise `false`. Omitted on observed branches.

**C6 — evidence completeness (clarification).** In §I, "the window's events" means all of them, in ledger order,
not a sample.

## 4. Impact

| Area | Impact |
|---|---|
| Compatibility | Unknown ids and E3 tighten what valid diagnoses look like. No change to any non-unknown claim, link, value, or the six canonical meanings. |
| Schema | Id pattern: subject segment allows `-`; unknown claims must match `^c:unknown_(model_unexplained_idle\|rule_not_applicable\|missing_relationship\|insufficient_window\|conflicting_facts):`; non-unknown ids must start with one of the eight kind prefixes. Schema version stays `atlas-diagnosis/0.1` (pre-release, no conforming producer exists). |
| Answer key | None. `diagnosis-expectations.json` carries no claim ids; generator unchanged; `--check` reproduces the same sha256. |
| Implementation | Rename unknown ids; extend the E3 check to all links; add `branch_interval` and pass it from the service; implement C4 and C5; attach complete evidence. |
| Fixtures, M1/M2/M3 | None. |

## 5. Migration

Muse applies C1–C6 together with the implementation-only corrections from the M4 review, on top of the refrozen
contract commit, as a true descendant.

## 6. Regression

All M4 tests plus: T-UNKNOWN-IDS (two unknowns on one subject coexist; world-level unknown id validates), T-E3-LINKS
(deterministic `limited_by` or `blocks`-linked to a bounded claim is rejected), T-INTERVAL (simulated `t < tB`,
`t > tH`, and missing interval are rejected at facade and service), T-ITEMWORK (pack source has no step names; a mini
world with a renamed order step yields the same `assembly_blocking`), T-ONSET-PARENT (baseline 19:00 Fry overload
has `onset_t` 18:15:00 and `onset_in_parent = true`). M1, M2 (28/28, hashes unchanged), M3 Playwright, Signet,
`oracle --check`, `derive-expectations.mjs --check`.

## 7. Why Fable escalation is not needed

Every change is local to the M4 contract, removes an ambiguity or closes a gap in the direction the frozen design
already states, and moves no fixture, hash or canonical diagnosis meaning. No foundational boundary changes.

## 1. Problems (contract level only)

1. **Assumption shown, but no template.** §X1 and case 9 say the manager assumption is "attached and shown"; §O has
   no template for it and §R says the browser shows only server lines. A conforming implementation cannot show it.
2. **Forbidden word contradicts a required template.** §O inherits the M4 §E list, which bans `revenue`, while the
   required `R_ECONOMICS` text contains `no revenue is assumed`. Both cannot hold literally.
3. **The M4 numeral post-check cannot apply literally.** M4 §L checks every numeral against the claim's `values`.
   M5 lines print world-local clock times, rates and currency that are formatted, not raw, values.
4. **`R_RANK` describes only the operational objective,** and its "conditional variant" has no fixed text. Once the
   economic objective ranks by net effect (required by §J/§K and case 5b), the frozen text would misstate the
   ranking rule.
5. **`R_ECONOMICS` does not say which rate it prints** when the objective is economic at a non-base value.
6. **`station=` on the service has no defined meaning.** Filtering a finished set leaves `top`, `ranking` and
   `set_hash` describing candidates that are not in the set.
7. **The inspector's horizon is unspecified** (`horizon_t` is required by §Q), and its error behaviour is undefined.
8. **"error recorded" for `insufficient_evidence` (§K) has no field** in the frozen schema (`additionalProperties: false`).
9. **T-GENERALITY asks for renamed rule ids,** but the accepted M4 pack resolves world rule ids literally (an M4 LOW
   bundled into CCR-003). A world with renamed rule ids is refused by `diagnoseAtTime` before M5 runs, so the test
   cannot pass without CCR-003 work that §Y keeps out of M5.

## 2. Normative changes

**C1 — `R_ASSUMPTION` (new template).**

| Template | Text |
|---|---|
| `R_ASSUMPTION` | `ASSUMED · Observed state: {resource_name} is on shift with no assigned station at {start_hhmm}. Duties outside the modeled stations are not represented in this simulation.` |

- **Emitted** for a candidate iff `eligibility.eligible = true` and `assumptions` contains the frozen string
  `resource has no modeled assignment at the source; any unmodeled duties are not represented`. One line per such
  candidate. (Infeasible candidates are never simulated, so no simulated result depends on the assumption.)
- **Position:** immediately after that candidate's `R_CANDIDATE` line and before any of its result lines
  (`R_DELTA`, `R_OVERLOAD_END`, `R_TRADEOFF`, `R_NEW_OVERLOAD`, `R_ECONOMICS`, `R_RANK`, `R_DOMINATED`).
  `R_AUTHORITY` remains the last line of every set's explanation.
- **Class:** `claim_class: assumed`. The first sentence restates observed modeled state (`on_shift` true and
  assignment null at `start_t`, already `derived` eligibility evidence); the second states what the model omits.
  A line's class is the weakest of its parts (§N), so the line is `assumed`. It never raises any other value's class.
- **Meaning:** the line states only that the observed modeled state has the resource on shift with no station, and
  that duties outside modeled stations are absent from the model. It does not say the resource is free, has no other
  responsibilities, is or stays available, or that the move is safe or authorised.
- **Canonical rendering** (`emp_06`, both windows, start 18:20 world-local):
  `ASSUMED · Observed state: Sam is on shift with no assigned station at 18:20. Duties outside the modeled stations are not represented in this simulation.`
- The structured `assumptions` string is unchanged (it is frozen in the answer key).

**C2 — Forbidden-word post-check, exact behaviour.** For every M5 line:
1. Start from the rendered line. Remove the text substituted for `*_name` placeholders (`resource_name`,
   `from_name`, `to_name`, `station_name`, `dominator_names`), as in M4 §L.
2. Only for an `R_ECONOMICS` line: if the line ends with the exact literal
   `(delay cost only; no revenue is assumed).`, remove that literal once. No other template, position or wording
   is exempt. Variants such as `revenue is assumed`, `no revenue is modeled`, or the literal anywhere else are not exempt.
3. Scan the remainder for each term of M4 §E (`cause`, `caused`, `causes`, `because of`, `due to`, `resulted in`,
   `led to`, `unhappy`, `revenue`, `should`, `recommend`) and `will`, `guarantee`, `profit`, whole-word,
   case-insensitive. Any match throws `RecommendationError('FORMAT_VIOLATION')`.

The guard still rejects every affirmative or unsupported revenue statement. Only the one fixed negation that states
revenue is not part of the economics model passes.

**C3 — Objective-aware `R_RANK` and `R_ECONOMICS`.** `R_RANK` has exactly four fixed variants:

| Objective | Status | Text |
|---|---|---|
| operational | recommended | `Ranked {rank}: lowest order time in system among non-dominated candidates without new overloads.` |
| operational | conditionally_recommended | `Ranked {rank} (conditional): lowest order time in system among non-dominated candidates with new overloads.` |
| economic | recommended | `Ranked {rank}: largest net effect at the {value_key} rate among non-dominated candidates without new overloads.` |
| economic | conditionally_recommended | `Ranked {rank} (conditional): largest net effect at the {value_key} rate among non-dominated candidates with new overloads.` |

`{value_key}` is `low`, `base` or `high`. `R_RANK` lines carry `claim_class: simulated` under `operational` and
`assumed` under `economic` (§N). `candidate.claim_class` keeps labelling the simulation record and stays `simulated`
as the schema requires. Under `economic` the objective-dependent outputs carry `assumed` through `top.claim_class`
and the line classes.

`R_ECONOMICS` prints the rate and `net_effect` for the objective's `economic_value_key` under `economic`, and for
`base` under `operational`. The rate for `base` is the world value; `low` and `high` are `set.sensitivity.values`.

**C4 — Numeral post-check for M5 (replaces the literal M4 §L numeral rule for M5 lines).** After step 1 of C2,
every numeral token (`\d+(\.\d+)?`) in the line must equal, numerically and ignoring sign, a number from the
template's sources below. Otherwise throw `RecommendationError('FORMAT_VIOLATION')`.

| Template | Numeral sources |
|---|---|
| `R_CANDIDATE`, `R_ASSUMPTION` | hour and minute of `window.start_t` (and `window.end_t` for `R_CANDIDATE`) as world-local `HH:MM` (04-time: world offset) |
| `R_DELTA` | `delta.order_time_in_system_s`, `delta.orders_completed_in_window`, `delta.stations[to].queue_burden_s` |
| `R_OVERLOAD_END` | `minutes_earlier = floor((baseline.stations[to].overload_last_t − metrics.stations[to].overload_last_t) / 60)` |
| `R_TRADEOFF` | the trade-off's `baseline` and `scenario` |
| `R_NEW_OVERLOAD` | `metrics.stations[station].overload_s` |
| `R_ECONOMICS` | the rate and `by_value[key].net_effect` per C3 |
| `R_RANK` | `rank` |
| `R_INFEASIBLE`, `R_DOMINATED`, `R_NO_ACTION`, `R_AUTHORITY` | none |

`R_OVERLOAD_END` is emitted iff both `overload_last_t` values are non-null and `minutes_earlier ≥ 1`. Canonical
top: `SIMULATED · Fry overload ends 65 minutes earlier.` `dominator_names` is the dominating candidate ids,
comma-separated, in `dominated_by` order.

**C5 — `station=` scope.** On `/api/recommendations` and its evidence route, `station=<id>` restricts the candidate
pool **before** evaluation. It is equivalent to `candidate_ids` = the generated candidates whose `to` is `<id>`,
intersected with `candidates=` when both are given. `candidates`, `ranking`, `top`, `sensitivity`, `set_id` and
`set_hash` are computed from that pool. A set is never filtered after construction. An empty pool returns
`no_action` / `NO_SUPPORTED_INTERVENTION`, exactly as an empty `candidate_ids` filter does today.

**C6 — Inspector horizon, rendering, errors (§R).**
- The inspector requests `horizon_t = min(t + 4200, range.max_t)` of the observed register as already served by M3.
  4200 s is the frozen M2 comparison-window length. It is a presentation constant, not domain logic.
- Every server line is inserted as text (`textContent`), never as HTML, in server order. A line whose `claim_class`
  is `assumed` gets the ASSUMED chip, which therefore covers `R_ASSUMPTION`. The browser writes no assumption prose.
- A non-200 response shows `Recommendations unavailable: {error.code}` and no recommendation lines. `R_AUTHORITY` is
  shown whenever any recommendation line is shown.

**C7 — `insufficient_evidence` error.** `atlas-recommendation/0.1` has no field for the error. For V0, "error
recorded" means the candidate carries `status: insufficient_evidence` with null simulation, metrics and economics.
No field may be added. A structured error field is deferred to the next schema version. No V0 fixture path
produces this status.

**C8 — §Y.** M5 now has one CCR: CCR-006. The CCR-003 note is unchanged.

**C9 — T-GENERALITY scope for M5.** The renamed-ids world renames persons, stations and their skill strings
(structurally, in `attrs.skills`, keeping the CCR-003 `st_` convention and recipe step ids). It must yield identical
statuses, metrics, ranking and top, mapped back by id. M5 code must contain no rule-id literals; that is checked by
source search, as T-PACK does. Renaming world rule ids stays with CCR-003.
